# streamstats

Консольная утилита для потокового анализа файлов с событиями (логами) в форматах CSV и JSONL. Читает файлы построчно, считает статистику и сохраняет итоги в JSON-отчёт.

## Возможности

- Чтение файлов **CSV** и **JSONL**.
- **Потоковая обработка**: файл читается построчно, в памяти хранятся только счётчики, а не сами события. Файл любого размера обрабатывается за одинаковый объём памяти.
- Статистика:
    - общее число событий;
    - число событий по уровням и по источникам;
    - top-5 источников ошибок (`ERROR` и `CRITICAL`);
    - первая и последняя метки времени.
- Несколько файлов за один запуск: статистика объединяется в один итог.
- Два режима работы с некорректными строками: остановка на первой ошибке (по умолчанию) или пропуск с флагом `--skip-invalid`.
- JSON-отчёт выводится в файл (`--output`) или в стандартный вывод.
- Поддержка Unicode (кириллица и другие символы в `source` и `message`).

### Формат входных данных

Каждое событие состоит из четырёх полей:

|Поле|Описание|
|---|---|
|`timestamp`|Время в формате ISO 8601, например `2026-10-07T09:00:00+00:00`|
|`level`|Один из `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` (регистр важен)|
|`source`|Источник события, непустая строка|
|`message`|Текст сообщения, строка|

CSV содержит заголовок `timestamp,level,source,message`:

```csv
timestamp,level,source,message
2026-10-07T09:01:00+00:00,ERROR,db,Connection failed
```

JSONL содержит по одному JSON-объекту на строку:

```jsonl
{"timestamp": "2026-10-07T09:00:00+00:00", "level": "INFO", "source": "loader", "message": "Start reading"}
{"timestamp": "2026-10-07T09:01:00+00:00", "level": "ERROR", "source": "db", "message": "Connection failed"}
```

## Использование

### Установка

```bash
pip install -e .
```

### Запуск

```bash
python -m streamstats analyze INPUT [INPUT ...] --format csv|jsonl [--output REPORT.json] [--skip-invalid]
```

| Аргумент         | Описание                                                                  |
| ---------------- | ------------------------------------------------------------------------- |
| `INPUT`          | Один или несколько входных файлов (в одном формате)                       |
| `--format`       | Формат входных файлов: `csv` или `jsonl`                                  |
| `--output`       | Файл для JSON-отчёта. Если не указан, отчёт выводится в стандартный вывод |
| `--skip-invalid` | Пропускать некорректные строки, а не останавливаться на первой            |

Файлы обрабатываются по очереди, в порядке указания, и их статистика складывается в один общий итог. Все файлы в одном запуске должны быть одного формата.

### Примеры

```bash
# один файл, отчёт в терминал
python -m streamstats analyze events.csv --format csv

# несколько файлов, отчёт в файл
python -m streamstats analyze day1.jsonl day2.jsonl --format jsonl --output report.json

# пропуск некорректных строк
python -m streamstats analyze events.csv --format csv --skip-invalid
```

### Формат отчёта

Для файла с шестью событиями отчёт выглядит так:

```json
{
  "total": 6,
  "skipped": 0,
  "levels": {
    "DEBUG": 0,
    "INFO": 2,
    "WARNING": 1,
    "ERROR": 2,
    "CRITICAL": 1
  },
  "sources": {
    "web": 2,
    "db": 1,
    "auth": 1,
    "loader": 1,
    "scheduler": 1
  },
  "top_error_sources": {
    "auth": 1,
    "db": 1,
    "web": 1
  },
  "first_timestamp": "2026-10-07 08:55:00+00:00",
  "last_timestamp": "2026-10-07 12:14:00+03:00"
}
```

- `skipped` — число пропущенных строк (при `--skip-invalid`).
- `top_error_sources` — до пяти источников `{источник: число ошибок}`. Сортировка по убыванию числа ошибок, при равенстве по имени источника (по алфавиту), поэтому порядок всегда одинаковый.
- `first_timestamp` и `last_timestamp` равны `None`, если событий нет.

### Вывод программы

- **stdout** — только JSON-отчёт (если не задан `--output`).
- **stderr** — предупреждения о пропущенных строках и сообщения об ошибках.
- **Код возврата**: `0` при успехе, `2` при ошибке (отчёт в этом случае не создаётся).

## Описание модулей

Данные проходят по цепочке: файл → парсер → валидация → анализ (аккумулятор) → отчёт.

- `errors.py` — иерархия исключений (см. раздел «Обработка ошибок»).
- `models.py` — `Level`, `Event` и `validate_record`: превращает «сырой» словарь в `Event` или бросает `InvalidEventError`. Проверяет наличие полей, допустимый `level`, непустой `source` и метку времени. `iter_events` соединяет парсер и валидацию и решает, что делать с плохой строкой: остановиться с ошибкой (файл и номер строки в сообщении) или записать `WARNING` и продолжить. 
- `parsers.py` — генераторы `parse_csv` и `parse_jsonl`, выдают `(номер_строки, запись)` и не валидируют данные. Номер строки считается по исходному файлу. Ошибки формата строки (например, оборванный JSON) они не бросают, а выдают как значение, иначе генератор завершился бы и режим `--skip-invalid` не смог бы продолжить чтение.
- `analysis.py` — `Accumulator`: счётчики по уровням и источникам, источники ошибок, минимальная и максимальная метки времени. События нигде не накапливаются. `analyze_events` пропускает события всех файлов через один общий аккумулятор, поэтому статистика объединяется сама.
- `report.py` — превращает аккумулятор в словарь и сериализует в JSON с `ensure_ascii=False`, чтобы кириллица осталась читаемой.
- `cli.py` — `StreamStatsParser` (бросает `CLIConfigError` вместо выхода из `argparse`), `parse_arguments` описывает команду `analyze` и её аргументы, `check_arguments` проверяет то, что `argparse` проверить не может: существование входных файлов и несовпадение `--output` со входом.
- `__main__.py` — `main()`: настраивает логирование, запускает анализ, записывает отчёт и перехватывает ошибки.

## Обработка ошибок

```
StreamStatsError                 # базовое исключение пакета
├── UnsupportedFormatError       # неподдерживаемый формат файла
├── InvalidEventError            # некорректное событие
│   └── InvalidTimestampError    # некорректная метка времени
└── CLIConfigError               # ошибка конфигурации CLI
```

`InvalidTimestampError` наследуется от `InvalidEventError`, чтобы один `except InvalidEventError` ловил обе ошибки, и режим `--skip-invalid` пропускал строки с неверной меткой времени так же, как и остальные.

|Ситуация|Исключение|
|---|---|
|Оборванный JSON, JSON не является объектом|`InvalidEventError`|
|Отсутствует поле, неизвестный `level`, пустой или нестроковый `source`|`InvalidEventError`|
|Метка времени не разбирается как ISO 8601|`InvalidTimestampError`|
|Формат не `csv` и не `jsonl`|`UnsupportedFormatError`|
|Файл не найден, `--output` совпадает со входом, неверные аргументы|`CLIConfigError`|

**По умолчанию** обработка останавливается на первой ошибке. Сообщение содержит файл и номер строки, программа завершается с кодом `2`, отчёт не создаётся:

```
Ошибка: events_bad.csv:3: Некорректный source: ''
```

**С `--skip-invalid`** плохие строки пропускаются:

1. в лог пишется `WARNING` с файлом, номером строки и причиной;
2. счётчик `skipped` увеличивается на единицу;
3. обработка продолжается, итоговый код возврата равен `0`.

```
WARNING | streamstats.models | events_bad.jsonl:2: пропущена строка: Некорректный JSON: Expecting ',' delimiter
WARNING | streamstats.models | events_bad.jsonl:4: пропущена строка: Пропущенные поля: source
```

Особенности разбора:

- Номер строки в сообщениях и логах — номер строки исходного файла, в том числе для многострочных записей CSV.
- Значение `null` в JSON и слишком короткая строка CSV считаются отсутствующим полем.
- Уровень регистрозависим: `info` вместо `INFO` считается ошибкой.

Все `StreamStatsError` перехватываются в одном месте, в `main()`: сообщение уходит в stderr, возвращается код `2`. Так выглядят и ошибки данных, и ошибки аргументов.
